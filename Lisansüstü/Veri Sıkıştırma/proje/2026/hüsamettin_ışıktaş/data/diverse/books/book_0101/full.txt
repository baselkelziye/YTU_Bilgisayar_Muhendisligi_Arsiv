From Wikipedia, the free encyclopedia

Compact encoding of digital data

"Source coding" redirects here. For the term in computer programming, see [Source code](/wiki/Source_code "Source code").

"Decompression software" redirects here. For the code for calculation of diving decompression schedules, see [Decompression algorithm](/wiki/Decompression_algorithm "Decompression algorithm").

In [information theory](/wiki/Information_theory "Information theory"), **data compression**, **source coding**,[[1]](#cite_note-Wade-1) or **bit-rate reduction** is the process of encoding [information](/wiki/Information "Information") using fewer [bits](/wiki/Bit "Bit") than the original representation.[[2]](#cite_note-mahdi53-2) Any particular compression is either [lossy](/wiki/Lossy "Lossy") or [lossless](/wiki/Lossless "Lossless"). Lossless compression reduces bits by identifying and eliminating [statistical redundancy](/wiki/Redundancy_(information_theory) "Redundancy (information theory)"). No information is lost in lossless compression. Lossy compression reduces bits by removing unnecessary or less important information.[[3]](#cite_note-PujarKadlaskar-3) Typically, a device that performs data compression is referred to as an encoder, and one that performs the reversal of the process (decompression) as a decoder.

The process of reducing the size of a [data file](/wiki/Data_file "Data file") is often referred to as data compression. In the context of [data transmission](/wiki/Data_transmission "Data transmission"), it is called source coding: encoding is done at the source of the data before it is stored or transmitted.[[4]](#cite_note-Salomon-4) Source coding should not be confused with [channel coding](/wiki/Channel_coding "Channel coding"), for error detection and correction or [line coding](/wiki/Line_coding "Line coding"), the means for mapping data onto a signal.

Data compression algorithms present a [space–time complexity trade-off](/wiki/Space%E2%80%93time_tradeoff "Space–time tradeoff") between the bytes needed to store or transmit information, and the [computational resources](/wiki/Computational_resource "Computational resource") needed to perform the encoding and decoding. The design of data compression schemes involves balancing the degree of compression, the amount of distortion introduced (when using [lossy data compression](/wiki/Lossy_data_compression "Lossy data compression")), and the computational resources or time required to compress and decompress the data.[[5]](#cite_note-Tank-5)

## Lossless

[[edit](/w/index.php?title=Data_compression&action=edit&section=1 "Edit section: Lossless")]

Main article: [Lossless compression](/wiki/Lossless_compression "Lossless compression")

Lossless data compression [algorithms](/wiki/Algorithm "Algorithm") usually exploit [statistical redundancy](/wiki/Redundancy_(information_theory) "Redundancy (information theory)") to represent data without losing any [information](/wiki/Self-information "Self-information"), so that the process is reversible. Lossless compression is possible because most real-world data exhibits statistical redundancy. For example, an image may have areas of color that do not change over several pixels; instead of coding "red pixel, red pixel, ..." the data may be encoded as "279 red pixels". This is a basic example of [run-length encoding](/wiki/Run-length_encoding "Run-length encoding"); there are many schemes to reduce file size by eliminating redundancy.

The [Lempel–Ziv](/wiki/Lempel%E2%80%93Ziv "Lempel–Ziv") (LZ) compression methods are among the most popular algorithms for lossless storage.[[6]](#cite_note-Optimized_LZW-6) [DEFLATE](/wiki/DEFLATE "DEFLATE") is a variation on LZ optimized for decompression speed and compression ratio,[[7]](#cite_note-7) but compression can be slow. In the mid-1980s, following work by [Terry Welch](/wiki/Terry_Welch "Terry Welch"), the [Lempel–Ziv–Welch](/wiki/Lempel%E2%80%93Ziv%E2%80%93Welch "Lempel–Ziv–Welch") (LZW) algorithm rapidly became the method of choice for most general-purpose compression systems. LZW is used in [GIF](/wiki/GIF "GIF") images, programs such as [PKZIP](/wiki/PKZIP "PKZIP"), and hardware devices such as modems.[[8]](#cite_note-8) LZ methods use a table-based compression model where table entries are substituted for repeated strings of data. For most LZ methods, this table is generated dynamically from earlier data in the input. The table itself is often [Huffman encoded](/wiki/Huffman_coding "Huffman coding"). [Grammar-based codes](/wiki/Grammar-based_codes "Grammar-based codes") like this can compress highly repetitive input extremely effectively, for instance, a biological [data collection](/wiki/Data_collection "Data collection") of the same or closely related species, a huge versioned document collection, internet archival, etc. The basic task of grammar-based codes is constructing a context-free grammar deriving a single string. Other practical grammar compression algorithms include [Sequitur](/wiki/Sequitur_algorithm "Sequitur algorithm") and [Re-Pair](/wiki/Re-Pair "Re-Pair").

The strongest modern lossless compressors use [probabilistic](/wiki/Randomized_algorithm "Randomized algorithm") models, such as [prediction by partial matching](/wiki/Prediction_by_partial_matching "Prediction by partial matching"). The [Burrows–Wheeler transform](/wiki/Burrows%E2%80%93Wheeler_transform "Burrows–Wheeler transform") can also be viewed as an indirect form of statistical modelling.[*[citation needed](/wiki/Wikipedia:Citation_needed "Wikipedia:Citation needed")*] In a further refinement of the direct use of [probabilistic modelling](/wiki/Probabilistic_model "Probabilistic model"), statistical estimates can be coupled to an algorithm called [arithmetic coding](/wiki/Arithmetic_coding "Arithmetic coding"). Arithmetic coding is a more modern coding technique that uses the mathematical calculations of a [finite-state machine](/wiki/Finite-state_machine "Finite-state machine") to produce a string of encoded bits from a series of input data symbols. It can achieve superior compression compared to other techniques, such as the better-known Huffman algorithm. It uses an internal memory state to avoid the need to perform a one-to-one mapping of individual input symbols to distinct representations that use an integer number of bits, and it clears out the internal memory only after encoding the entire string of data symbols. Arithmetic coding applies especially well to adaptive data compression tasks where the statistics vary and are context-dependent, as it can be easily coupled with an
